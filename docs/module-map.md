# Module map — Ka0s Quick Comms

Every non-vendored file, its responsibility, and the TOC load order. `libs/` (Ace3, LibSharedMedia,
LibDataBroker, LibDBIcon, LibCustomGlow-1.0, LibKa0s v1.81.0 (media/icons held to CLAUDE.md's `LibKa0s icons:` line, all)) and `tests/_kit/` are vendored and never edited.

## Load order (the TOC)

`libs\LibCustomGlow-1.0\LibCustomGlow-1.0.xml` loads before LibKa0s; LibKa0s-Glow-1.0 (`core/GlowSetup.lua`, `NS.GlowLib`) resolves it at call time, for `modules/Glow.lua`.

`Bindings.xml` (root, not a TOC line): Toggle Comms Pads, `CLICK QuickCommsTogglePads:LeftButton`,
first, then Open Comms Dial 1–4, each a `CLICK QuickCommsDial<n>:Toggle` binding (a dial's key is this
binding since 2026-10-20), every line in `category="BINDING_HEADER_QUICKCOMMS"` (launcher-§6), so WoW's
key bindings menu draws them in a Ka0s Quick Comms section of their own. The client reads it from the
addon's root by name, and the standard allows it there (layout-§1, toc-file-§4 (standard v2.80.0)); the
dials' labels are set in `modules/Dial.lua`, Toggle Comms Pads' and the category's in
`settings/SlashVerbs.lua`.

`tools/` holds the dev-only generators (`derive-gameids.py` and its
`client_tables.py`, `gen-dial-textures.py`, `gen-shine-textures.py`) and the shine preview renderer
(`render-shine-preview.lua`, which loads the addon headless through the test harness and dumps what it
painted, and `render-shine-preview.py`, which composites the dump): never loaded by the client or the
TOC, `.pkgmeta`-ignored (layout-§1).

Why each position is load-bearing or conventional is written on the comment line above its entry in
`QuickComms.toc` (toc-file-§5); a TOC line carries the file path alone. The planned modules and the
files they add are listed in design spec §4.2.
